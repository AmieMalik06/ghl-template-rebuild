Case study · GoHighLevel website template

Fixing a broken mobile menu and rebuilding the header for a contractor website template

A US marketing agency builds websites for home-service contractors from one GoHighLevel template. On phones the menu was broken: links didn't open, the icons overlapped, and the inner pages showed an outdated menu. I found the cause, rebuilt the navigation on every page, and redesigned the header in the style of the agency's best-performing site. The template still works for any client.

The brief

What the client asked for

  • ✓Fix the mobile view. Visitors couldn't scroll, and tapping a service in the menu did nothing.
  • ✓Give the Home page the same slim navigation bar as the agency's reference site.
  • ✓Add a Get Free Quote button at the top right.
  • ✓Add more color and motion, because the old header looked plain next to the reference.
  • ✓Keep everything driven by Custom Values so it works for every client.
  • ✓Work on a test copy only, without touching any live client site.
Diagnosis

Why the mobile menu broke

The Home page looked fine, so the problem seemed random. Opening each page in the builder's Layers panel showed the actual cause.

Main cause

Two outdated headers on every inner page

The Home page used one shared header. The 30+ service, service-area and contact pages each had two older ones, a desktop-only and a phone-only version. The phone version was broken and still listed old pages like About Us and Reviews.

Links

Menu links opened new tabs

Every menu item was set to open in a new tab, which often fails on phones, especially inside the Facebook and Instagram browsers where most ad traffic lands.

Links

Home and Contact jumped instead of navigating

Both were set to page anchors (#home, #contact), so on pages without those sections they did nothing.

Template

Text that didn't follow Custom Values

The business name in the header was hard-coded, so every new client site showed placeholder text until someone edited it by hand.

Process

How I did it

  1. Worked on a duplicate

    I copied the template into a test sub-account so live client sites were never at risk.

  2. Reproduced the bug

    I tested every page in a phone-sized preview and traced the broken menu to the old header sections in the Layers panel.

  3. Replaced the headers on all pages

    On each of the 30+ inner pages I swapped the two old headers for the single global header. Now one edit updates the whole site.

  4. Fixed every link

    I set all menu items to open the actual page in the same tab, and pointed Home and Contact at real pages instead of anchors.

  5. Redesigned the header with Custom Values

    I added a site-wide stylesheet that reads the client's two brand colors from Custom Values. The header, menu, stripe and buttons recolor themselves for each client.

  6. Refined it from the client's feedback

    The client asked for a bigger, bolder menu in a more professional font and slimmer buttons. I switched to Montserrat at 17px bold and reduced the button size.

Built for reuse

Two Custom Values recolor the whole header

The agency launches a new site by filling in Custom Values. I kept that workflow: changing colors__main and colors__secondary restyles the header for a new client with no edits in the builder. Try a few brand palettes below.
